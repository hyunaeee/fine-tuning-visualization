# 반응형 UI 회귀 점검

마지막 확인: 2026-09-15. Chromium 기반 인앱 브라우저에서 프로덕션 빌드로 확인했습니다.
이 문서는 수동 브라우저 QA 기록이며 자동 레이아웃 테스트를 의미하지 않습니다.

## 재현했던 문제와 수정

- 실무 적용 시나리오: 좁은 3열 내부의 `nowrap` 때문에 긴 전후 비교 문구가 옆 칸을 침범했습니다. 설명, 비교 카드, 실행 버튼을 별도 행으로 나누고, 섹션 폭 640px 이하에서는 비교 카드를 세로로 배치합니다.
- 사이드바가 있는 태블릿: 화면 폭만으로 판단하던 입력·출력, 모델 목록, 레시피 그리드를 각 컨테이너의 실제 가용 폭에 맞춥니다.
- 긴 콘텐츠: JSON 예시, 레시피 이름·다이얼 값, 전달 파일명이 줄바꿈되도록 하고 flex/grid 자식의 최소 너비를 해제합니다. 중요한 값은 말줄임표로 숨기지 않습니다.
- 선택 상태: 밝은 파란 배경 위의 흰 제목, 어두운 박스 위의 어두운 라벨, 파란 버튼 위의 흐린 화살표 색상을 수정했습니다.
- 320px 화면: 단계 이동의 가로 넘침과 첫 화면 다이얼 설명의 과도한 줄바꿈을 정리했습니다. 3D 장식은 콘텐츠를 침범하지 않도록 범위를 줄였습니다.

## 확인한 범위

| 범위 | 화면 폭(px) | 확인 내용 |
| --- | --- | --- |
| 시작 화면의 4가지 업무 목적 | 320, 390, 768, 900, 1024, 1280, 1440 | 입력·출력, 예시 선택, 전후 답변, 실무 시나리오의 내부 가로 넘침 없음 |
| 자료·기준 → 동작 설계 → 검증 설계 → 저장·공유 | 320, 390, 768, 1024, 1440 | 이동 동작, 모델·레시피 카드, 긴 문서 예시, 전달 파일 확인 |
| 4가지 전달 대상 | 320, 768, 1280 | 선택 상태와 파일 카드 내부 가로 넘침 없음 |

브라우저의 `clientWidth`/`scrollWidth`와 실제 스크린샷을 함께 확인합니다.
기계 장식·입출력 연결 화살표·전달 카드의 원형 장식처럼 의도적으로 경계를 넘는 장식은
텍스트 넘침과 구분합니다. 단계의 보조 설명과 미리보기 기록의 말줄임표는 의도된 요약입니다.

## 다시 확인하는 방법

1. `npm run check`로 lint, 타입 검사, 도메인 테스트 57개, 프로덕션 빌드, HTML 테스트 2개를 실행합니다.
2. `npm run start -- --hostname 127.0.0.1 --port 3008`로 빌드를 열고 위 폭별로 검사합니다. 새 빌드 후에는 서버 재시작과 브라우저 새로고침을 진행합니다.
3. 특히 `임의 약속 → 담당자 검토`, `일반 문의 → 결제 장애`, `미측정 → 평가 필요`가 각각 자기 박스 안에 있어야 합니다.
4. 문서 구조화 목적의 JSON 답변, 긴 저장 레시피 이름, `modely-organize-demo.json`을 확인합니다. 테스트 중 기존 레시피를 삭제하지 않습니다.
5. 선택된 예시·전달 대상의 제목, 레시피 설정 지표의 라벨, 시작 버튼 화살표가 배경 위에서 읽히는지 확인합니다.
6. 프로덕션 배포 후에도 실제 사이트의 데스크톱·모바일 화면을 다시 확인합니다.
