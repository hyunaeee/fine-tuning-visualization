2026-09-12 기준. 모델리는 실제 학습 백엔드에 연결하기 전 단계의 프런트엔드 제품 데모입니다.

## 모듈 경계

- `app/`: Next.js 라우트, 메타데이터, 전역 스타일 진입점, 오류 경계
- `features/studio/components/`: 시작 화면, 예시 자료, 모델 목록, 다이얼, 레시피 북, 미리보기, 전달, 주변 레이아웃
- `features/studio/hooks/`: React 상태 조합, 브라우저 구독·타이머 생명주기, 공유·다운로드 피드백
- `features/studio/domain/`: 타입, 상태 전환, 입력 검증, 시뮬레이션, 전달 문서·공유 설정의 직렬화
- `features/studio/data/`: 시연용 모델 목록, 업무 예시와 기본 레시피
- `features/studio/storage/`: 주입 가능한 저장소 인터페이스와 구독 가능한 레시피 저장 상태
- `features/studio/browser/`: 클립보드·Blob 다운로드의 브라우저 경계
- `features/studio/styles/`: 기초 스타일, 레이아웃, 시작 화면, 단계, 콘솔, 반응형 순서의 CSS

도메인 함수는 React와 브라우저 런타임에 의존하지 않습니다. 컴포넌트에는 필요한 상태와 액션의 타입만 전달하고, 단계 간 공유 상태는 `studioReducer`가 관리합니다. 전달 대상 같은 화면 안에서만 쓰는 상태는 해당 화면에 둡니다.

## 데이터 수명과 오류 처리

- 작업 중인 초안과 최근 8개의 미리보기 기록은 현재 세션에만 존재합니다. ‘새 AI 만들기’는 세션을 새로 시작합니다.
- 저장한 레시피는 `modely-recipes-v2`의 `{ version: 2, recipes: [...] }` 형식입니다. v2가 없는 경우에만 `modely-recipes-v1`을 읽습니다.
- 구형 레시피에는 해당 업무의 기본 설명과 질문을 보충합니다. 구형 원본 저장 키는 자동 삭제하지 않습니다.
- 손상된 항목은 화면에 적용하지 않고 알립니다. 완전히 읽을 수 없는 저장 데이터는 쓰기로 덮어쓰지 않습니다.
- 저장 성공 뒤에만 저장 목록을 바꿉니다. 최초 읽기 이전의 저장을 막고, 탭 간 저장 이벤트를 구독하며 쓰기 전에 최신 데이터를 읽습니다. localStorage는 다중 사용자 데이터베이스나 원자적인 동시 편집을 제공하지 않습니다.
- 공유 링크의 URL fragment에 버전이 있는 설정을 담습니다. URL fragment는 HTTP 요청에 포함되지 않지만, 링크를 가진 사람은 내용을 볼 수 있습니다. 화면에서 목표 설명과 질문의 포함 여부를 안내합니다.
- 공유 링크와 저장 데이터 모두 같은 입력 검증을 거칩니다. 선언된 필드만 복사하므로 단계·파일명 등 임의의 상태를 주입할 수 없습니다.
- 다운로드 문서에는 `kind: modely-demo-handoff`와 시뮬레이션 범위를 명시합니다. 파일 선택은 실제 학습·데이터 처리와 구분합니다.

## 검증과 배포

### 업무 목적과 검증 계획 (2026-09-15)

- `data/purposes.ts`는 목적별 문제, 학습 대상 동작, 대안, 데이터 준비 규칙과 평가 항목의 단일 원본입니다. `PurposePlan`이 첫 화면과 검증 단계에서 재사용하며 인계 JSON도 같은 데이터를 직렬화합니다.
- 기존 `support`·`brand`·`organize` ID를 유지하고 `technical`을 추가했습니다. 저장 형식과 공유 버전을 바꾸지 않아 기존 사용자 설정을 그대로 읽습니다. 사용자 작성 설명·질문은 자동 교체하지 않습니다.
- 검증 계획은 `evaluationPlan.status: "not-run"`입니다. 다이얼 기반 `configuration-simulation`과 모델의 실제 품질 평가는 섞지 않습니다. 성능 개선을 암시하는 가상 수치 대신 실패 유형과 목표 출력 예시를 표시합니다.
- `tests/purposes.test.ts`에서 모든 목적의 카탈로그·질문·레시피·공유·인계 문서 정합성, 예외 이관, 정보 부족 분류, JSON의 null 보존과 구형 브랜드 설정 호환성을 확인합니다.

Node.js 24를 `.nvmrc`, package engines, GitHub Actions에 고정했습니다. `npm run check`가 린트 → 타입 → 도메인 테스트 → Next.js 빌드 → 생성된 HTML 검사를 실행합니다. CI는 main push와 pull request에서 같은 명령을 실행합니다.

모델 API 키, 학습 작업 큐, 데이터 업로드 서버, 사용자 인증은 구현하지 않았습니다. 실제 연결 시에는 서버에서 공급사 호출·자격 증명을 관리하고, 시뮬레이션과 별개의 실제 평가 결과 타입·처리 경로를 추가해야 합니다. 현재 지표를 실측 모델 성능으로 재사용하지 않습니다.
