# Modely · 모델리

반복되는 업무 오류를 줄이기 위해 **데이터·출력 동작·검증 기준을 설계하는 파인튜닝 워크스페이스**입니다. 전문적인 개선 목적을 비개발자도 이해하도록 입체 다이얼, 예시 비교와 재사용 가능한 레시피로 풀어낸 프런트엔드 제품 데모입니다.

[라이브 데모](https://fine-tuning-visualization.vercel.app/) · [포트폴리오](https://hyunaeee.github.io/aengdo-portfolio/archive.html#modely)

## 쉬운 조작을 위한 UI

파란색·아이스 블루 테마와 CSS로 만든 입체 다이얼을 사용합니다. 본문은 13–14px 중심으로 유지합니다. 첫 화면의 ‘업무 기준 반영’ 다이얼은 정책 조건·분류·필드·검수 기준이 예시 출력에 어떻게 반영되는지 보여줍니다. 실제 학습률이나 모델 가중치를 조절하지 않습니다.

데모 모델 3개를 먼저 보여주고 나머지 모델과 자세한 설명은 펼쳐볼 수 있습니다. ‘목적 선택 → 자료·기준 → 동작 설계 → 검증 설계 → 저장·공유’ 순서로 안내합니다. 모바일, 키보드 조작, 포커스 표시와 모션 감소 설정을 지원합니다.

## 왜 파인튜닝인가?

파인튜닝을 모든 문제의 해법으로 제시하지 않습니다. 목적을 선택하면 해결할 오류, 학습으로 맞출 동작, 먼저 비교할 방법, 평가 항목이 함께 바뀝니다.

- 지시·말투: 프롬프트 조정을 먼저 검토합니다.
- 최신 사실·정책: 검색(RAG)으로 필요한 근거를 제공합니다.
- JSON 형식: 구조화 출력과 스키마 검사를 먼저 적용합니다.
- 반복적인 분류·필드 매핑·지시 준수 실패: 검수된 예시로 SFT를 검토하고, 학습과 분리한 평가셋으로 기준 모델과 비교합니다.

공식 근거: [모델 최적화 워크플로](https://developers.openai.com/api/docs/guides/model-optimization), [SFT와 평가 우선 원칙](https://developers.openai.com/api/docs/guides/supervised-fine-tuning). **2026-09-15 확인:** OpenAI 파인튜닝 플랫폼은 신규 사용자 접근이 제한되며 기존 계정도 지원·종료 일정을 확인해야 합니다. 이 제품은 특정 공급사에서의 학습 실행 가능성을 보장하지 않습니다.

## 무엇을 체험하나요?

- 정책 준수 상담, 기술지원 티켓 분류, 업무 문서 구조화, 브랜드 콘텐츠 검수 중 목적 선택
- 필요한 입력 자료와 예상 출력, 사용 전후 답변 예시 비교
- 목적에 따라 정렬되는 모델 카탈로그
- 규칙 준수, 친절함, 간결함, 표현 다양성 다이얼 조정
- 조작에 반응하는 예시 답변과 설정 성향 표시, 실제 평가와 구분한 검증 계획
- 모델·목적·다이얼 설정을 레시피로 저장하고 다시 불러오기
- 운영자, 웹사이트, 개발자, 대행사별 결과 전달 화면 미리보기

## 입력과 출력 예시

| 목적 | 입력 예시 | 출력 예시 |
| --- | --- | --- |
| 정책 준수 상담 | 제공 정책, 승인·이관 상담 사례 | 조건 확인·판단 보류·예외 이관 초안 |
| 기술지원 분류 | 증상·영향 범위, 전문가 라벨 | 장애 유형·우선순위·담당 팀·분류 근거 |
| 문서 구조화 | 원문, 필드 정의와 정답 | 고정 필드 JSON, 미확인 값 `null` |
| 콘텐츠 검수 | 승인 상품 정보, 검수 전후 문구 | 수정 문구와 근거 없는 주장 제거 사유 |

각 흐름은 미리 구성한 예시로 체험합니다.

## 현재 구현 범위

현재 공개판은 **프런트엔드 제품 데모**입니다.

- 예시 답변은 React 상태와 규칙 기반 템플릿으로 변경됩니다.
- 다이얼 점수와 모델 정렬은 시연용이며 실제 평가 결과가 아닙니다. 가상의 성능 향상 수치는 제거하고 실패 유형과 목표 출력의 차이를 보여줍니다.
- 모델 API 호출이나 파인튜닝 학습 작업을 실행하지 않습니다.
- 파일 선택은 파일명만 표시하며 파일 내용을 읽거나 서버에 업로드하지 않습니다.
- 레시피는 같은 브라우저의 `localStorage`에 보관하며, 모델·다이얼뿐 아니라 직접 쓴 목표 설명과 테스트 질문도 복원합니다. 계정 간 동기화는 없습니다.
- 현재 설정·예시 결과·업무 목적·검증 계획을 JSON으로 내려받거나, 같은 설정을 복원하는 링크를 복사할 수 있습니다. 검증 계획은 `status: "not-run"`이며 공유 링크에는 목표 설명과 질문도 포함됩니다.
- 웹 위젯·API·고객별 서비스 배포는 전달 방식의 UI 예시입니다. 실제 고객 서비스나 학습된 모델을 발급하지 않습니다.
- 카탈로그는 코드에 정의한 데이터이며 공급사의 실제 지원 여부를 자동 조회하지 않습니다.

실제 서비스로 확장하려면 서버 측 모델 공급사 연결, 데이터 처리, 학습 작업 관리, 독립된 평가셋, 계정별 저장소와 고객용 배포가 필요합니다.

## 로컬 실행

Node.js 24를 사용합니다. `.nvmrc`, package engines와 CI에서 같은 주 버전을 지정합니다.

```sh
npm ci
npm run dev
```

개발 서버는 기본적으로 http://localhost:3000 에서 실행됩니다.

```sh
npm run check
npm start
```

`npm run check`는 린트, 타입 검사, 도메인 동작 테스트, 프로덕션 빌드와 생성된 HTML 검사를 순서대로 실행합니다. `npm test`로 도메인 테스트만 빠르게 실행할 수 있습니다. GitHub Actions에서도 같은 검사 묶음을 실행합니다.

## 코드 구성

- `app/`: 라우트 진입점, 메타데이터, 오류 경계와 스타일 진입점
- `features/studio/components/`: 업무 단계별 UI와 재사용 가능한 콘솔 구성 요소
- `features/studio/hooks/`: React 상태 조합, 미리보기 생명주기와 저장소 구독
- `features/studio/domain/`: 브라우저 없이 검증 가능한 상태 전환, 데이터 검증, 시뮬레이션, 전달 문서
- `features/studio/data/`: 시연용 모델 목록과 업무·레시피 예시
- `features/studio/storage/`, `browser/`: 저장, 클립보드와 파일 다운로드 경계
- `features/studio/styles/`: 레이아웃, 화면, 콘솔, 반응형 스타일
- `tests/`: 실패 경로를 포함한 동작 테스트와 실제 빌드 HTML 검사
- `vercel.json`: Vercel 배포 설정

[구조 점검 결과와 설계 설명](docs/ARCHITECTURE.md)에 변경 이유, 모듈 경계, 저장 데이터 호환성과 실제 모델 연결 시의 확장 지점을 정리했습니다.

Next.js, React, TypeScript로 구현하고 Vercel에 배포했습니다. API 키 없이 데모를 실행할 수 있습니다. 환경 파일과 Vercel의 로컬 연결 정보는 Git에서 제외합니다.
